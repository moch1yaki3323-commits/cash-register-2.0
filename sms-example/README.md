# 選用簡訊後端範例

你尚未申請服務商，所以此範例不會自動啟動或發送簡訊。HTML 可獨立使用；先透過排隊複製公版即可。此範例以 Twilio 示範，並非已替你申請服務、付款或選定供應商。若選其他供應商，只需替換 `send_twilio()`；前台合約保持一致。

後端環境變數（在主機安全設定輸入，不要寫進 HTML、Git 或聊天）：

- `SMS_APP_TOKEN`：自行產生至少 32 字元的操作憑證，給受信任操作員；前台僅存在記憶體。
- `SMS_ALLOWED_ORIGIN`：收銀網頁來源，完整到 scheme 與 port，例如 `http://127.0.0.1:8000`。正式站使用 HTTPS。
- `SMS_TWILIO_ACCOUNT_SID`、`SMS_TWILIO_AUTH_TOKEN`：Twilio 憑證。
- `SMS_TWILIO_FROM`：服務商核准的寄件號碼／識別碼，請勿填你的私人號碼。實際是否可在台灣送出、是否保留 Sender ID、驗證及費率依服務商與電信商規定。
- `SMS_DB_PATH`（選填）：冪等紀錄 SQLite 檔案位置，需可寫、備份及限制讀取權限。

執行 `python3 server.py`，預設只監聽 127.0.0.1:8787；正式部署需 HTTPS 反向代理。前台「設定 → 排隊 → 通知設定」填 `https://你的後端/api/sms`。不要把後端金鑰放進靜態網站。範例限制每分鐘 10 次請求，正式營運仍需依使用量設計個別操作員登入、發送配額、帳單上限、憑證輪替與服務商送達回呼。

API：POST `/api/sms`，Authorization: Bearer 操作憑證，JSON：

```json
{"requestId":"不可重複的請求ID","phone":"+886912345678","message":"您的001號已完成，請到A28取貨。","ticketNumber":"001"}
```

只有 HTTP 200 且 `{"status":"accepted","messageId":"服務商訊息ID"}` 才視為服務商接受。此狀態不代表送達。逾時／未知時不要直接重送；先查服務商紀錄。同一 `requestId` 重試不重送。前台每次按發送會產生新 ID，因此請先確認未重複送出。後端不記錄手機與訊息原文；前台號碼牌備份包含手機，需妥善保管。

這次只執行模擬服務商的後端測試；未做真實簡訊發送。
